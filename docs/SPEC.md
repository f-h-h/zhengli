# 整理（zhengli）系统规格清单

> 版本：2026-09-02 · 本文按代码现状整理，标注 ✅ 为已实现并验证。

## 1. 系统概述

| 项   | 说明                                                                     |
| --- | ---------------------------------------------------------------------- |
| 形态  | Go 单二进制（前端 go:embed 内嵌）+ SQLite 嵌入式数据库，零外部依赖                           |

## 2. 数据模型

### 2.1 Room 房间

`name, room_w, room_d, room_h`（米）。房间尺寸决定 3D 墙体轮廓。

### 2.2 Location 位置容器（15 种类型）

- 字段：`room_id, parent_id, name, location_type, x/y/z（中心坐标，米）, w/h/d, rot_y（弧度）, color, is_activity_zone, is_cardbox, geom_group`

- **业务归属（parent\_id）与几何坐标完全解耦**：系统不校验坐标与归属一致性，由用户保证

- `geom_group`：几何联动组（置物架架体+层板、床头柜台面+抽屉），纯几何概念不影响归属树

**类型权限矩阵** ✅：

| 类型                | 可挂子容器 | 可存物品 | 备注                      |
| ----------------- | ----- | ---- | ----------------------- |
| cabinet 衣柜        | ✅     | ✅    | <br />                  |
| drawer 抽屉/隔间      | ✅     | ✅    | 3D 渲染带面板+拉手             |
| shelf\_layer 层板   | ✅     | ✅    | <br />                  |
| box 收纳箱           | ✅     | ✅    | <br />                  |
| cardbox 纸箱        | ✅     | ✅    | <br />                  |
| luggage 行李箱       | ✅     | ✅    | <br />                  |
| wall\_mount 挂墙收纳  | ✅     | ✅    | 门上只能挂这种                 |
| table 桌/台面        | ✅     | ✅    | <br />                  |
| hanger 挂衣杆        | ❌     | ✅    | <br />                  |
| tray 托盘           | ❌     | ❌    | <br />                  |
| ground\_spot 地面区域 | ❌     | ✅    | <br />                  |
| furniture 家具      | ❌     | ❌    | 不能作 parent              |
| obstacle 障碍物      | ❌     | ❌    | 必须顶层                    |
| door 门            | ❌     | ❌    | 唯一例外：可挂 wall\_mount（挂钩） |
| window 窗户         | ❌     | ❌    | 必须顶层                    |

**硬规则** ✅：

- 嵌套深度 ≤ 3 层（根=0）

- parent 必须存在于同一房间

- obstacle/door/window 必须顶层（parent\_id = null）

- 门上只能贴挂钩（wall\_mount）

- 系统不自动生成任何 location（预设模型库是用户显式点选）

### 2.3 Item 物品

- 字段：`location_id, name, remark, qty, image_url`

- 无 3D 几何尺寸，不参与嵌套深度计算

- 图片：本地 `uploads/items/` + 相对路径，支持上传/更换/删除/大图预览

## 3. 功能清单

### 3.1 房间与容器管理 ✅

- 房间增删改、房间切换

- 容器增删改（名称/类型/尺寸/坐标/颜色/归属）

- 收纳树：按 parent\_id 层级展示，展开/添加子容器/面包屑

- **预设模型库**（「＋顶层」点选）：家具（床/书桌/衣柜/床头柜组合/置物架 2–6 层组合）、收纳（收纳箱/纸箱/行李箱/收纳袋/落地衣架）、墙面（门/窗户/壁挂空调/挂钩）；预设预填尺寸+智能摆放位置

- **柜内隔层网格生成**：柜类容器填「N 层 × M 列」一键均分内部空间生成 drawer 隔间（1–8 层 × 1–6 列，柜壁留 2cm 壳厚）

### 3.2 物品管理 ✅

- 物品增删改、数量 qty、备注

- 按容器录入、归属变更（移动）

- 物品图片：上传（jpg/png/webp/gif，≤10MB）、缩略图、全屏预览

### 3.3 搜索寻物 ✅

- 名称/备注模糊搜索，结果带位置面包屑（`房间 › 柜 › 隔间 › 箱`，沿 parent\_id 上溯，非 3D 坐标推导）

- **3D 定位**：搜索结果点「📍」→ 自动切房间+切 3D 视图 → 目标容器呼吸闪烁 3 秒 + 整条祖先链橙色描边 + 相机对准

### 3.4 3D 场景 ✅

- 浅色主题：白底卡片、浅蓝灰背景、白地板、软阴影、ACES 色调映射

- 按类型复合建模：桌（顶板+四腿）、门（门板+把手）、窗（框+高透玻璃）、落地衣架（底盘+立杆+横杆）、行李箱（圆角体+拉杆+提手）、抽屉（面板+金属拉手）、挂钩（背板+托板）、其余圆角盒

- 柜类半透明渲染：内部隔间/箱子透出可见

- 尺寸网格参考线；类型配色中高饱和度

### 3.5 拖拽交互 ✅

- **直接拖**：按住物体拖（桌面=鼠标，移动端=单指），沿地面 XZ 平移；Shift+拖 = 调高度 Y；gizmo 箭头仍可精确单轴微调；旋转/缩放走工具栏模式

- **组联动**：geom\_group 成员整体平移、整组保存

- **墙吸附**：门/窗/挂墙物拖到距墙 0.3m 内自动贴墙+转向（四向法向厚度统一 d/2）

- **边对齐吸附**：任意容器拖拽中，边缘接近墙体或其它实体边缘（≤8cm 容差、共面重叠≥5cm）自动对齐齐平；整组联动同步平移，Shift 调高 Y 不参与

- **墙体钳制**：拖拽实时限制在房间范围内、底面不入地板

- **碰撞检测**：物体间 AABB 相交即弹回最近合法位置；豁免=业务祖先/后代、同 geom\_group、区域标记类（ground\_spot/obstacle/window）；贴面（摞放）允许

- 选中：蓝色描边 + 详情面板联动

- 几何校验仅拖拽时软约束，表单输入/CSV 导入不硬拦（§5-5 原则）

### 3.6 数据导入导出 ✅

- locations CSV 导入（mode=add/replace，corner→center 坐标换算）/ 导出

- items CSV 导入 / 导出（含归属链名称）

- 房间布局快照 JSON 导出（**导入恢复未实现**，见优化点）

### 3.7 布局校验提示 ✅

- obstacle 与物品几何重叠 → 黄色警告提示（不拦截）

### 3.8 API 一览 ✅

```
房间    GET/POST /api/rooms · PUT/DELETE /api/rooms/{id}

        GET/PUT/DELETE /api/locations/{id} · PATCH /api/locations/{id}/geom
```

### 3.9 移动端 ✅

- <768px 手机布局：底部标签（搜索/收纳树/3D），单指拖物体、空白单指转视角、双指缩放

- ≥768px 平板走桌面三栏布局

- manifest 已配，可添加到主屏幕全屏运行

## 5. 补充装（在用/备用）方案设计

### 5.1 问题本质

同一物品存在两份记录需求：

- **在用装**：qty 通常 =1，放在使用位置（如洗手台）

- **补充装**：qty = N，放在存储位置（如储物柜）

- 生命周期：**用完 → 从补充装取一件顶上 → 补充装见底 → 补货**

### 5.2 方案：同组库存（stock\_group）

**数据变更**（items 表增两列，老库自动迁移）：

```sql
ALTER TABLE items ADD COLUMN stock_group TEXT;      -- 同一产品共享组名
ALTER TABLE items ADD COLUMN min_qty INTEGER DEFAULT 0; -- 组内总量的补货阈值
```

- 「沙宣洗发水 400ml」在用（洗手台，qty=1）和补充（储物柜，qty=2）共享 `stock_group="洗发水"`

- 不引入独立"产品表"——本系统是收纳台账不是 ERP，名称+组即够

**三条核心操作**：

1. **用完了**（在用物品上按钮）

   - 同组查补充装（stock\_group 相同、qty>0）→ 有：弹选单 → 扣减该补充装 qty−1，在用装 qty 恢复 1（物理上你把备用瓶拿过来）

   - 无补充装：提示「无备用，建议补货」→ 自动写入待购清单

2. **补货**（补充装物品上按钮，或待购清单一键）

   - 补充装 qty+N（默认整包）

   - 也可新建补充装记录并自动继承 stock\_group

3. **待购清单**（新视图）

   - 汇总所有 `min_qty>0` 且「组内总量（在用+补充）≤ min\_qty」的组

   - 显示：产品名、现存总量、建议购买量（min\_qty×2 − 现存量）

   - 打勾 = 假想已购（提示录入到补充装位置）

**与现有模型的关系**：

- 深度/权限/位置全部不变——补充装只是普通 item

- CSV 导出加 `stock_group,min_qty` 两列，导入兼容

- 搜索结果照常显示，补充装条目带「备」徽标

### 5.3 备选方案对比

| 方案              | 思路                      | 评价                     |
| --------------- | ----------------------- | ---------------------- |
| A 单记录数量         | 一条记录 qty=3 混存           | 在用和备用位置不同，位置语义崩溃 ❌     |
| **B 同组双记录（推荐）** | stock\_group 关联         | 改动小、位置语义清晰、搜索/3D 全兼容 ✅ |
| C 独立产品表         | products + inventory 两表 | ERP 化过度设计，超出收纳场景 ❌     |
